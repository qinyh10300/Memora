# Model selection, team moderation, memory search and sidebar

Status: in-progress
Owner: Codex
Last updated: 2026-08-06

## Outcome

登录用户可以在 GPT、Claude 和 Gemini 之间切换 Chatbot 模型；团队号加入改为由团队
所有者审核的申请，所有者可以批准、拒绝申请并移除普通成员；个人和团队记忆库提供紧凑的
关键词、标题、时间和成员筛选；桌面侧栏可以收起为只保留品牌标志与展开按钮的窄栏。

## Context and evidence

- 产品规则要求新记忆默认私有，检索必须先应用身份、workspace 和可见性过滤。
- ADR 0004 让团队号直接创建 membership，并将审批和成员移除推迟；本计划按最新产品需求
  通过 ADR 0005 覆盖这两个决定。
- API 已有可配置模型注册表和动态模型列表，Web 已有模型选择器，不需要让领域代码依赖某个
  供应商 SDK。
- `POST /search` 已提供授权后的混合检索和作者、时间过滤，但缺少关键词专用模式、标题投影
  与当前记忆库的筛选界面。

## Scope

### In scope

- 通过模型注册表提供 GPT、Claude、Gemini 三个可选模型，并保持当前 GPT 为默认模型。
- 团队号提交产生待审核申请；所有者查看、批准和拒绝申请。
- 所有者移除普通成员；被移除成员的活动 session 自动回到其个人空间。
- 个人记忆库按全文关键词、标题和时间范围筛选。
- 团队记忆库在相同筛选上增加成员筛选，并继续只返回调用者有权访问的记录。
- 桌面侧栏收起、展开与本地偏好记忆；移动端继续使用完整覆盖式抽屉。
- OpenAPI 契约、迁移、权限测试、Web 交互测试和真实浏览器验收。

### Non-goals

- 新增管理员角色、角色编辑、所有权转移、主动退团、团队删除或团队号轮换。
- 向外部邮箱发送邀请、审批通知或为未注册账号预留邀请。
- 跨 workspace 搜索、模糊成员身份推断或管理员读取成员私有记忆。
- 暴露模型的隐藏思维链或供应商私有推理内容。

## Assumptions and open questions

- 已确认：团队所有者按注册邮箱直接添加成员仍立即生效；团队号加入需要审批。
- 已确认：审批只创建 membership，不主动切换申请人的其他浏览器 session。
- 已确认：移除成员不删除团队内历史记录；成员立即失去访问权限，其已共享记录仍是团队
  workspace 的历史内容并保留作者标注。
- 已确认：记忆库明确使用关键词模式，不因 embedding 不可用而阻塞筛选。

## Design and boundaries

- 新增独立 `workspace_join_requests` 表。待审核申请不是 membership，因此不会进入任何授权
  列表、检索候选、提示词或资产读取路径。
- 申请以 `workspace_id + user_id` 唯一，拒绝后可再次提交；审核记录保存状态、审核者和时间。
- 批准申请与创建 membership 在同一事务完成。移除 membership 前，将该用户仍指向团队的
  session 更新为其个人 workspace。
- `memories.title` 是从不可变正文首个非空 Markdown 行派生的检索投影；修订创建新投影，
  删除正文时同步清除。正文仍是事实来源。
- `POST /search` 保持 JSON 请求，增加 `KEYWORD` 模式和 `ALL` / `TITLE` 字段范围。所有筛选
  均叠加在现有服务端授权查询上，前端筛选不承担权限职责。
- 模型选择只通过供应商无关的注册表 ID 进入现有 Chat 端口。

## Acceptance criteria

- [ ] Chatbot 模型菜单稳定显示 GPT、Claude、Gemini，选择会随 Chat 请求发送。
- [ ] 提交有效团队号后不会立即获得团队权限；所有者批准后才出现 membership。
- [ ] 所有者可拒绝申请和移除普通成员；非所有者、匿名用户和跨团队请求均被拒绝。
- [ ] 所有者不能移除自己；成员被移除后其相关 session 回到个人空间且不能读取团队内容。
- [ ] 个人记忆库可按全文关键词、标题及起止日期独立或组合筛选。
- [ ] 团队记忆库可增加成员筛选，其他成员私有记忆始终不出现在结果中。
- [ ] 桌面窄栏只显示 Memora 标志与展开按钮；移动抽屉和键盘操作不回归。

## Verification

- 自动化检查：API 单元/集成测试、Web 组件测试、类型检查、lint、构建与 `make check`。
- 集成验证：空库升级及 0011 到新迁移的升级/降级，验证 title 回填和申请表约束。
- 手工或浏览器验证：三模型选择、侧栏收展、筛选弹层、申请审批和成员移除。
- 安全与权限验证：未批准申请无访问权、非所有者管理拒绝、移除后会话回退、团队私有记录
  不可检索。

## Rollout and recovery

- 先部署向后兼容的 nullable title 与申请表迁移，再部署 API/Web。旧客户端提交团队号会收到
  新的待审核响应，不会误建 membership。
- 回滚应用前可先停用审核入口；迁移降级删除申请表和 title 投影，不删除 memory 正文、
  membership 或 workspace。
- 模型注册配置缺失时继续使用现有默认模型；单个可选模型失败由现有 AI 降级路径处理。
