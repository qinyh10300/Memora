# Feishu-style workspace console

Status: completed

Owner: Yihua Qin and coding agent

Last updated: 2026-07-26

## Outcome

把 Memora 从“带空间切换的聊天历史页”重构成“以空间工作流为中心的记忆工作台”。左侧导航优先呈现记录、问答、团队记忆、分析和成员权限；conversation 历史降为辅助导航。整体交互参考飞书工作台与管理后台的分组导航、空间上下文和成员目录心智模型，但不复制其复杂企业管理能力。

## Problem diagnosis

- 当前左栏的第一层仍是“新建对话 / 对话 / 记忆库 / 最近对话”，用户需要先理解 conversation，才能找到真实任务。
- 空间切换已经存在，但空间下面没有稳定的功能地图，组织感弱。
- 团队共享记录只是记忆库的一个页签，缺少成员、共享范围和团队资产视角。
- 报告能力藏在自然语言路由中，用户无法发现“分析”是 Memora 的核心价值。
- 视觉层次主要依赖灰色背景，缺少飞书式的分组、状态、工作台卡片和清晰反馈。

## Product decisions

1. 使用“记录记忆”而不是“上传记忆”。v0.3 只接收纯文本，“上传”会错误暗示文件、图片或批量导入能力。
2. 左栏按用户任务分组：
   - 记录记忆：创建或进入用于捕捉想法的 conversation。
   - 记忆问答：恢复 conversation，通过统一聊天框检索。
   - 团队记忆：浏览当前空间中主动共享的记录，并可切换回自己的记录。
   - 分析：通过既有报告 API 生成个人或团队时间段报告。
   - 成员与权限：查看当前空间成员、角色和共享规则。
3. conversation 历史保留，但位于功能导航之后，不再承担产品主信息架构。
4. “团队记忆”不是管理员读取所有成员数据的入口。它只展示当前服务端授权查询返回的 `WORKSPACE` 记录；其他成员私有记录不存在于候选数据中。
5. 成员页 v0.3 只读。邀请、部门树、角色编辑和成员移除仍是后续独立权限项目，不在前端伪造不可用操作。
6. 分析页调用现有 `/reports`，结果不自动写入 conversation；报告范围、时间和证据来源必须显式展示。

## Interaction design

- 空间选择器保持在左栏顶部，作为所有功能的上下文边界。
- “记录记忆”使用高优先级动作样式；工作台模块使用分组导航和明确图标。
- 主区域根据模块使用不同信息密度：
  - Chat 保持安静、低干扰。
  - 团队记忆使用统计摘要、成员筛选和记录卡片。
  - 分析使用报告模板、范围/时间配置和结构化结果。
  - 成员权限使用成员目录与权限说明。
- 页面切换使用轻量进入动效；侧栏、弹层、卡片 hover 和加载状态使用一致的 160–220ms 过渡。
- 移动端仍使用覆盖式导航抽屉，所有模块在 390×844 视口无横向滚动。

## Scope

### In scope

- 重构 Web 左栏、标题和模块路由状态。
- 增加团队记忆的统计、成员筛选与权限文案。
- 增加分析工作台并接入既有报告 API。
- 增加只读成员与权限目录。
- 更新组件测试、产品文档和浏览器验收。

### Non-goals

- 新建部门、邀请/移除成员、角色授权或组织树编辑。
- 文件、图片、语音或批量上传。
- 新的分析后端、定时报告或 report 持久化。
- 修改 memory 可见性模型、conversation 权限或部署拓扑。

## Acceptance criteria

- [x] 用户进入任一团队空间后，无需理解 conversation 即可发现记录、问答、团队记忆、分析和成员权限。
- [x] 团队记忆只展示主动共享记录，可按成员筛选，并明确说明不包含私有内容。
- [x] 分析页可选择个人/团队范围和最近 7/30/90 天，生成包含证据来源的结构化报告。
- [x] 成员页展示当前空间成员与角色，不向普通成员暴露虚假的管理操作。
- [x] 记录仍默认私有；空间切换后所有模块使用同一个服务端活动 workspace。
- [x] 桌面与 390×844 移动视口关键路径通过，控制台无应用错误。

## Verification

- `make check`

- Docker 重建后检查 Web/API health
- 浏览器执行：空间切换、记录入口、团队记忆筛选、分析生成、成员目录、移动侧栏

## Evidence and rationale

飞书的组织管理把“成员与部门”“角色/用户组”“可见范围”和“管理看板”拆成清晰模块，并且将组织架构可见性视为独立安全规则。Memora 借用这种“空间上下文 + 分组工作台 + 明确权限页面”的信息架构，但保持 v0.3 的数据模型和权限范围不变。
