# Web Search Timeout And Client Freshness

Status: completed
Owner: Codex
Last updated: 2026-08-05

## Outcome

修复明确联网调研在云雾工具链中累计等待后失败的问题，并确保部署后的页面刷新不会继续取得
旧版 HTML。保持授权检索、来源白名单、显式保存和失败时保留 Markdown 的现有边界。

## Evidence

- 2026-08-05 19:38 发起的旧同步请求调用 `/api/drafts/chat`，总耗时 447.2 秒，后端最终记录
  `provider_timeout`；当前聊天超时为 180 秒、联网搜索超时为 90 秒。
- 默认模型同时声明 tools 与 web_search。明确联网请求先让聊天模型选择工具，再执行 Responses
  联网，最后再次调用聊天模型，最坏路径约为 `180 + 90 + 180` 秒。
- 截图仍为部署前的结果卡片；当前首页响应为 `Cache-Control: s-maxage=31536000`，会允许共享
  代理长期复用旧 HTML，旧脚本因而继续调用同步接口。
- GitNexus 对 `_complete_with_draft_tools` 和 `chat_with_draft` 的上游影响均为 LOW、无直接调用方。

## Changes

- 对明确联网且不要求编辑 Markdown、保存或处理附件的提问，直接把云雾 Responses API 已生成的
  检索摘要转为 Chat 回答，并只引用该次返回的来源；不再追加两轮聊天模型调用。
- 明确联网但需要编辑或保存时，先执行确定性的联网搜索，再进行至多一次后续聊天编排。
- 保留 AUTO 模式下模型自主选择工具的能力，保留搜索失败时不覆盖 Markdown 的行为。
- Caddy 对 Web 文档响应覆盖为 `no-store`，静态内容仍由内容哈希保证一致性。
- 聊天继续使用 `gpt-5.6-terra`，Responses 联网使用独立的 `gpt-4.1-mini`；原始完整查询的
  本地真实请求验证后者 20.96 秒返回 8 个来源，而 Terra 和 `gpt-5.4-mini` 均在应用的
  90 秒上限内未完成这条宽查询。

## Completion summary

失败由两个问题叠加造成：旧 HTML 被一年期共享缓存复用，仍调用旧同步客户端；云雾工具链又用
`gpt-5.6-terra` 依次执行工具规划、Responses 联网和最终整理，累计 447.2 秒后超时。现在 Web
文档响应使用 `no-store`，同步与 SSE 共用优化后的后端路径。明确联网提问由独立的
`gpt-4.1-mini` 执行一次 Responses 搜索并直接形成带来源回答；只有明确编辑 Markdown 或保存时
才继续一次结构化聊天编排。聊天默认模型仍为 `gpt-5.6-terra`，授权检索与显式保存边界不变。
