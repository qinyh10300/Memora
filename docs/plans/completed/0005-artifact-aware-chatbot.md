# Artifact-aware personal Chatbot

Status: completed
Owner: Codex
Last updated: 2026-07-26

## Outcome

“记录想法”成为真正的个人 Chatbot：模型持续看到本次对话、当前 Markdown
工作区和经过服务端授权筛选的个人记忆。它可以回答记忆问题，也可以修改右侧
Markdown；任何修改实时进入未保存草稿，正式保存仍需要用户点击确认。

## Context and evidence

- `docs/product/brief.md` 要求草稿可由对话修改、事实回答有授权来源、AI 不代替用户保存。
- 当前 `POST /drafts/refine` 只接收当前 Markdown 和最新指令，模型看不到前序原话。
- 当前 `POST /chat/questions` 能做带引用的问答，但没有当前草稿和前端 capture 对话。
- 当前前端 `messages` 只用于渲染，没有发送给后端。

## Scope

### In scope

- 新增统一的个人草稿 Chatbot API，不破坏记忆详情现有的单次 AI 修改接口。
- 每轮发送有长度上限的完整 capture 会话与当前 Markdown。
- 服务端只从当前个人空间读取当前用户自己的活动记忆，并限制证据数量与正文总量。
- 模型返回结构化的聊天回复、草稿更新意图和完整 Markdown。
- 事实性回复返回可打开的原始记忆引用。
- 右侧 Markdown 在每轮成功响应后同步更新，保存仍为显式按钮操作。
- AI 不可用时保留当前草稿；首次陈述仍能进入基础草稿。

### Non-goals

- 自动保存、模型自行删除或修改正式记忆。
- 团队记忆、其他成员记录或跨空间检索。
- 多 conversation 持久化和流式 token 输出。
- 每轮把数据库全部正文无上限发送给模型。

## Design and boundaries

1. Web 将当前 Markdown 与 capture 会话发送到新的 Chatbot endpoint。
2. API 校验身份和个人空间，优先在当前用户整个个人记忆向量投影上做语义召回；
   embedding 不可用时降级为最近的活动记忆。
3. API 对记录条数、单条正文和总上下文设置上限，再结束数据库事务。
4. Chat adapter 接收系统规则、会话、当前 Markdown 和证据 JSON。
5. 模型输出结构化 JSON；服务端解析、限制长度，并在 `draft_changed=false`
   时强制保留当前 Markdown。
6. 外部调用后重新授权证据；授权变化时丢弃模型答案和引用。
7. 响应只更新未保存草稿，正式记忆写入仍走现有 `POST /memories`。

## Milestones

- [x] M1 — API 契约、结构化模型提示和授权个人证据；验证：API 测试。
- [x] M2 — Web 发送完整会话并展示回复、草稿和引用；验证：组件测试。
- [x] M3 — 真实模型、Docker 和浏览器验收；验证：`make check`、真实页面路径。

## Acceptance criteria

- [x] 用户第一次输入的原话会保留在后续模型上下文中。
- [x] “按我的原话恢复”可以从本次会话恢复草稿，而不是继续改写当前版本。
- [x] 普通记忆问题可以得到回复且带当前用户有权访问的来源。
- [x] 模型可以在一轮内回复用户并更新右侧完整 Markdown。
- [x] 其他用户私有记忆永不进入候选、提示词、响应或引用。
- [x] AI 失败、结构化输出无效或授权变化时，当前草稿不丢失。
- [x] Chatbot 不会自动写入正式记忆。

## Verification

- 自动化检查：API 权限/提示词/解析测试，Web 会话/草稿/保存边界测试，`make check`。
- 集成验证：Docker API/worker 健康，真实模型结构化响应。
- 手工或浏览器验证：原话恢复、连续修改、询问个人记忆、显式保存。
- 安全与权限验证：另一个账号的私有标记不会进入模型捕获 prompt。

## Rollout and recovery

新增 endpoint，保留 `/drafts/refine`，因此记忆详情和旧前端可继续工作。若真实
供应商结构化响应不稳定，可让 Web 临时回退旧接口；草稿完全在客户端，失败不需要
数据迁移或恢复。

## Decision log

- 2026-07-26：不把全部数据库正文无上限注入模型；使用服务端个人授权、数量和字符预算。
- 2026-07-26：保留点击保存边界；Chatbot 可以编辑草稿，但不能替用户提交正式记忆。
- 2026-07-26：明确的原话恢复不再调用模型；原因是这是精确的状态操作，不应受生成随机性影响。

## Completion summary

个人 capture 已从一次性改写器升级为 artifact-aware Chatbot。会话历史、当前
Markdown 和授权个人记忆在服务端形成清晰边界；模型可回答或更新草稿，事实回复
返回可打开引用。明确的原话恢复由服务端确定性执行，正式保存仍需要用户点击按钮。
本次没有数据库迁移，旧 `/drafts/refine` 保留供记忆详情继续使用。
