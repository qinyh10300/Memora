# Team workspaces and shared memories

Status: completed
Owner: Codex
Last updated: 2026-08-06

## Outcome

登录用户既可以继续使用默认个人空间，也可以创建或加入团队。团队所有者可以通过已注册
邮箱邀请成员；任意登录用户可以使用团队号加入。进入团队后，页面显示团队名称、团队号、
成员和角色。用户保存记忆时明确选择“仅自己”或“团队共享”，团队成员只能读取当前团队内
主动共享的其他成员记忆，并能看到每条记忆的作者。

## Context and evidence

- 产品规则要求所有新记忆默认 `PRIVATE`，共享必须由作者主动触发。
- ADR 0002 已确定 `PERSONAL` / `TEAM` 共用同一 workspace 模型、活动空间保存在服务端
  session，以及 memory 由 `workspace_id + author_id + visibility` 授权。
- ADR 0002 和当前个人 Markdown MVP 曾推迟邀请能力并隐藏团队入口；本计划依据用户的最新
  明确需求恢复该能力，并新增 ADR 覆盖旧范围限制。
- 后端已经存在团队创建、空间列表/激活、成员列表、memory 分享/撤回和授权检索基础；当前
  Web 登录后强制激活个人空间，并只加载当前用户的私有记忆。

## Scope

### In scope

- 创建团队并为创建者授予 `OWNER`。
- 为团队生成唯一的 12 位团队号；成员可复制，登录用户可通过团队号加入。
- 团队所有者通过已注册邮箱添加成员。
- 个人/团队空间切换并在同一 session 中保持当前选择。
- 团队详情、成员姓名与角色展示。
- 保存时选择 `PRIVATE` 或 `WORKSPACE`；默认始终为 `PRIVATE`。
- 团队记忆库展示本人私有记忆与所有成员共享记忆，并标明作者和可见性。
- 作者可以在团队空间内分享或撤回自己的记忆；撤回继续失效跨用户引用。

### Non-goals

- 向外部邮箱发送邀请邮件，或邀请尚未注册的账号。
- 移除成员、主动退团、所有权转移、角色编辑和团队删除。
- 共享 conversation、共同编辑、评论、审批或跨 workspace 检索。
- 公开互联网链接访问团队内容。

## Assumptions and open questions

- 已确认：团队号通过请求正文提交，不进入 URL 或访问日志。
- 已确认：新登录 session 默认进入个人空间；用户切换团队后，该 session 记住当前空间。
- 已确认：成员列表不公开登录邮箱，只显示昵称、角色和加入时间。
- 已确认：成员都可以查看并分享团队号；只有 `OWNER` 可以按邮箱邀请。
- 已确认：存在未保存草稿时阻止空间切换，避免草稿被意外保存到错误空间。

## Design and boundaries

- `workspaces.join_code` 只用于 `TEAM`，数据库唯一且可空；迁移为现有团队回填代码。
- `POST /workspaces/join` 校验限流、团队号和当前账号，幂等添加 `MEMBER` 并激活团队。
- `POST /workspaces/{id}/members` 仅允许该团队 `OWNER` 添加活跃的已注册用户。
- 所有空间激活仍通过服务端 membership 验证并更新 `user_sessions.workspace_id`，客户端不能
  自行声明可信 workspace。
- `POST /memories` 新增可选 `visibility`，缺省 `PRIVATE`；请求 `WORKSPACE` 时服务端再次
  验证当前空间为 `TEAM`。
- memory 列表继续复用统一授权查询：本人可见自己的私有与共享记录，其他成员只可见
  `WORKSPACE` 记录。详情、搜索、AI、引用、报告和受保护资产继续使用相同边界。
- 共享更新保持作者专属；个人空间拒绝创建或切换为 `WORKSPACE` 可见性。

## Acceptance criteria

- [x] 用户可创建团队，并在个人与多个团队空间间切换。
- [x] 所有者可通过已注册邮箱邀请成员；非所有者被拒绝。
- [x] 登录用户输入有效团队号后加入并进入团队；错误代码不暴露团队信息。
- [x] 团队页显示组织名、团队号、成员昵称、角色和加入时间。
- [x] 团队空间保存默认“仅自己”，主动选择后才成为“团队共享”。
- [x] 成员 B 可以看到成员 A 的共享记忆及作者，但不能通过列表、ID、检索、AI 或引用读取
      A 的私有记忆。
- [x] 撤回共享后，其他成员立即无法再读取该记忆，历史引用按现有规则失效。
- [x] 个人空间行为不回归，注册用户仍只自动获得自己的个人空间。

## Verification

- 自动化检查：`make check` 通过，包括 Ruff、ESLint、mypy、TypeScript、OpenAPI 契约、
  Next.js 生产构建、40 个 Web 测试和 89 个 API 测试。
- 集成验证：在临时 PostgreSQL 数据库完成从空库升级到 `0011`、降级到 `0010`，并验证旧
  团队升级时回填 12 位唯一团队号。
- 手工或浏览器验证：真实走通创建团队、按邮箱邀请、团队号加入、主动共享、跨账号作者标注
  与只读查看；桌面和 390px 移动端布局通过，浏览器控制台无警告或错误。
- 安全与权限验证：覆盖匿名拒绝、非所有者邀请拒绝、跨 workspace 隔离、私有记忆隔离、
  个人空间禁止共享、撤回共享和共享修订传播。

## Rollout and recovery

- 先迁移 nullable 唯一团队号并回填现有 `TEAM`，再发布依赖新字段的 API/Web。
- 回滚 Web/API 不会改变 memory 正文；旧客户端继续因 `visibility` 缺省而保存为私有。
- 数据库降级只删除团队号列；已有 membership 与共享 memory 保留，不做破坏性删除。
- 加入或邀请事务失败时整体回滚，不留下无效 membership；embedding 失败仍不影响 memory 保存。

## Completion summary

已交付个人与团队并存的 workspace 体验。团队所有者可创建团队并邀请已注册账号，用户也可
通过团队号加入；团队页展示成员和角色。新记忆仍默认私有，只有用户显式选择才共享给当前
团队，其他成员看到作者并保持只读。未包含外部邮件邀请、成员移除、退团和所有权转移。
