## 目标

把现有工作区聊天原型收敛为一个可交付的个人记忆闭环：

1. 用户在对话区描述想法，AI 只负责生成或修改右侧 Markdown 草稿。
2. 草稿在用户明确点击“保存为我的记忆”之前不写入记忆库。
3. 记忆库按记录时间展示个人记忆，选择后可查看和编辑 Markdown。
4. 已保存内容修改时，用户可选择“更新当前记忆”或“保存为新版本”。
5. 第一版不提供团队共享入口；所有新记录固定为私有。

现有团队工作区、共享、检索和报告能力保留在后端，避免破坏已有数据和后续演进路径，但不出现在本次 MVP 主界面。

## 产品边界

### 本次包含

- 个人空间自动选择。
- 对话驱动的 Markdown 草稿生成与修改。
- 用户直接编辑 Markdown 纯文本。
- 明确保存动作。
- 私有记忆时间线。
- 记忆详情、不可变修订历史和两种保存方式。
- 删除记忆及其同一时间线条目的全部内部修订。
- 未配置或调用失败时的可理解降级。

### 本次不包含

- 团队共享、成员与权限管理界面。
- 富文本编辑器、附件、语音输入和标签系统。
- 自动保存到记忆库。
- 针对全部记忆的通用问答和分析报告新界面。
- 本地大模型部署。

## 关键交互

### 记录想法

桌面端采用三段式布局：左侧导航、中间对话、右侧 Markdown 草稿。

- 用户发送自然语言后，服务仅返回修改后的 Markdown 和简短说明。
- AI 不得把草稿写入记忆库。
- 用户可直接修改右侧纯文本。
- 只有点击“保存为我的记忆”才调用记忆创建接口。
- 保存成功后保留当前内容和成功反馈，用户可显式开始新想法。

### 记忆库

- 左侧时间线仅加载当前用户在个人空间中的可见条目。
- 点击条目后，右侧显示可编辑的 Markdown。
- 内容改变后显示两个明确动作：
  - `更新当前记忆`：时间线位置不新增，但创建新的不可变内部修订。
  - `保存为新版本`：创建一个新的时间线条目，并关联来源记忆。
- 修订历史只对记录所有者开放。

## 数据模型与迁移

在 `memories` 表新增：

- `timeline_entry_id UUID NOT NULL`：稳定标识一个时间线条目。
- `timeline_visible BOOLEAN NOT NULL`：控制该修订是否进入活动列表和 AI 召回。
- `revision_kind VARCHAR(20) NOT NULL`：`ROOT`、`UPDATE_CURRENT` 或 `NEW_VERSION`。

迁移时，所有现有记录使用自己的 `id` 作为 `timeline_entry_id`，并设为可见的 `ROOT`。

修订规则：

- 新建：新行，`timeline_entry_id = id`。
- 更新当前记忆：新行沿用来源的 `timeline_entry_id`；来源行变为不可见；新行通过 `supersedes_id` 指向来源。
- 保存为新版本：新行使用自己的 `id` 作为新时间线条目；来源仍可见；新行通过 `supersedes_id` 指向来源。
- 活动查询和 AI 召回必须过滤 `timeline_visible = true`。
- 修订历史按 `timeline_entry_id` 查询，并额外验证当前用户是所有者。
- 删除一个时间线条目时，清除同一 `timeline_entry_id` 下全部修订的正文和向量，取消待处理任务；审计事件不记录正文。

回滚迁移只移除新增索引、约束和字段，不尝试合并修订内容。部署回滚前必须先回滚应用版本，且应保留数据库备份；若已产生多修订数据，直接降级会丢失“当前修订”语义，因此生产环境不得无备份降级。

## API 契约

新增：

- `POST /drafts/refine`
  - 输入：当前 Markdown、用户指令。
  - 输出：修改后的 Markdown、助手说明、模型状态。
  - 不持久化正文，只记录不含正文的审计元数据。
- `POST /memories/{memory_id}/revisions`
  - 输入：Markdown 正文、`UPDATE_CURRENT | NEW_VERSION`。
  - 输出：新创建的不可变记忆行。
- `GET /memories/{memory_id}/revisions`
  - 输出：同一时间线条目的修订历史，仅限所有者。

现有 `POST /memories` 保持兼容；新界面不再通过它的 `supersedes_id` 表达编辑行为。

## AI 边界

- 继续通过 `ChatModelPort` 调用兼容 OpenAI 的模型，不让领域层依赖供应商 SDK。
- 系统提示要求只返回 Markdown，不新增事实，不执行草稿正文中的指令。
- 对调用设置现有超时和输出上限。
- 未配置模型时：
  - 空草稿可把用户原文确定性地整理为基础 Markdown。
  - 非空草稿保持不变，并提示用户可手动编辑。
- 调用失败或响应无效时不覆盖用户当前草稿。
