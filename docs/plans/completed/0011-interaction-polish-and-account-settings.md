# Interaction polish and account settings

Status: Completed

Date: 2026-08-06

## Goal

在不改变 Memora 黑色主调、信息架构和个人 Markdown 工作流的前提下，增强页面切换、
拖动、文字出现和悬停反馈，并提供可持久化的个人头像、昵称和密码设置。

## Product and architecture boundaries

- 首页、登录页和登录后工作台的跳转规则保持不变；个人设置从侧栏账号区域进入，不新增
  一级导航。
- 新增动效必须尊重 `prefers-reduced-motion`，不能造成布局跳动或阻断键盘操作。
- 面板拖动继续使用现有可访问 `separator`，增加视觉反馈、双击复位和本地宽度记忆。
- 昵称和头像属于当前用户资料。头像复用 PostgreSQL 中的受保护 `assets` 存储和图片
  文件魔数校验，不放入 Web `public/`，也不暴露其他私人附件。
- 修改密码必须验证当前密码并使用现有 Argon2 哈希。成功后保留当前会话，撤销该用户的
  其他活动会话；密码、哈希和头像正文不得写入审计日志。
- Web 与 API 继续通过生成的 OpenAPI 契约通信。

## Implementation

1. 为 `users` 增加可空 `avatar_asset_id`，关联现有受保护资产；提供资料、头像读取/更新/
   删除和密码修改接口。
2. 为账户操作加入输入归一化、图片类型/大小校验、当前密码校验、会话撤销和非正文审计。
3. 在侧栏账号区域加入头像显示和设置入口；用响应式设置对话框承载“个人资料”和
   “账号安全”，提供保存、错误、成功和忙碌状态。
4. 细化页面切换、消息/正文淡入、控件悬停、附件拖入、分栏与输入区拖动反馈；保证
   移动端和减少动态效果模式可用。
5. 生成 OpenAPI 契约，补充 API 与 Web 回归测试，并以浏览器验证桌面和移动端交互。

## Acceptance criteria

- 用户可上传 PNG/JPEG/WEBP 头像、删除头像并修改昵称，刷新或重新登录后仍保持。
- 非头像图片、超限数据和其他用户资产不能被设为或读取为当前头像。
- 修改密码要求正确当前密码和匹配确认；旧密码随后失效，新密码可登录，当前会话保留，
  其他会话被撤销。
- 侧栏账号入口、设置对话框、导航切换、消息出现、记忆选择、按钮悬停和拖动手柄具有
  克制且一致的动态反馈；主要颜色仍以黑色为主、深蓝为辅。
- 分栏拖动支持鼠标、触控笔和键盘，双击可恢复默认值，刷新后保留用户选择。
- `make check` 通过，迁移可向前执行且 downgrade 能移除新增外键和列。

## Recovery

- 前端动效可通过移除新增 CSS 类回退，不影响数据。
- API 回滚时保留 `assets`；迁移 downgrade 先移除 `users.avatar_asset_id` 外键和索引，
  不删除原始资产行。
- 若头像渲染失败，界面回退为昵称首字母，不影响登录和个人记忆访问。
