# Mobile adaptation and popover overflow

Status: completed
Owner: Codex
Last updated: 2026-08-06

## Outcome

空间切换菜单在可拖动侧栏的任意桌面宽度下都完整可见；Memora 的公开首页、认证界面、记录工作区、记忆库、团队页和设置/团队弹窗在常见手机宽度下可阅读、可滚动、可操作，同时桌面端现有布局、比例和拖动行为保持不变。

## Context and evidence

- 相关产品规则：移动端仍必须保留个人/团队空间边界、默认私有可见性和保存前确认。
- 相关架构与 ADR：本次仅调整 Web 展示与交互，不改变 API、领域模型、权限或部署结构。
- 当前代码事实：桌面侧栏使用 `overflow: hidden` 保证可拖动收起效果，绝对定位的空间菜单因此在侧栏较窄时被裁剪；现有移动端规则集中在 `820px` 与 `620px` 断点。

## Scope

### In scope

- 修复空间切换菜单被侧栏和拖动分隔条遮挡。
- 补齐公开首页、登录/注册、应用主工作区、记忆库、团队页、设置和团队操作弹窗的移动端布局。
- 处理窄屏安全区、横向溢出、可滚动区域、按钮触达尺寸和长文本换行。
- 运行现有回归测试，并在桌面、平板和手机视口做浏览器验证。

### Non-goals

- 不重排或重新设计桌面端布局。
- 不改变 API、数据库、权限、模型调用或业务流程。
- 不引入新的前端依赖或设备专用页面。

## Assumptions and open questions

- [x] 以 `820px` 作为应用抽屉与单列工作区的主断点，以 `620px` 作为手机紧凑布局断点。
- [x] 桌面弹层允许越过侧栏边界覆盖主内容，移动端弹层保持在抽屉内部。

## Design and boundaries

桌面只改变空间菜单打开时的裁剪和层级，不改变网格列宽、面板尺寸或拖动逻辑。移动端规则全部限定在既有响应式断点内，通过单列、底部弹层、内部滚动和安全区 padding 适配，不复制业务组件。所有功能继续使用同一 DOM 和事件处理逻辑。

## Milestones

- [x] M1 — 空间菜单在侧栏最小、默认和加宽状态均完整可见；验证：浏览器测量菜单边界和截图。
- [x] M2 — 主要页面在 320、390、430 和 768 像素宽度可操作且无横向溢出；验证：浏览器逐页截图与 DOM 尺寸检查。
- [x] M3 — 桌面 1280 像素布局与拖动交互无回归；验证：桌面截图、交互测试和 `make check`。

## Acceptance criteria

- [x] 空间菜单不再被侧栏右边缘或拖动把手裁剪。
- [x] 320px 宽度下无页面级横向滚动，长标题、团队名和按钮文案不越界。
- [x] 移动端导航抽屉、设置、团队操作、模型选择、编辑与保存均可触达。
- [x] 移动端工作区滚动不会遮住输入框、保存栏或关键操作。
- [x] 大于 820px 的桌面网格、面板尺寸和拖动/吸附行为保持原样。

## Verification

- 自动化检查：`make check` 通过；45 个 Web 测试和 92 个 API 测试通过。
- 集成验证：生产构建、TypeScript、ESLint、Ruff、MyPy 和 OpenAPI 契约检查通过。
- 手工或浏览器验证：1280x720、768x1024、430x932、390x844、320x568 均无页面级横向溢出；浏览器控制台无警告或错误。
- 安全与权限验证：未修改权限和数据调用；团队空间的“仅自己/团队共享”控件在移动端仍可见。

## Rollout and recovery

无迁移。修改仅涉及 Web CSS、前端测试和文档；若出现回归，可独立回退本计划对应的响应式规则与弹层层级规则。

## Completion summary

空间切换菜单现在能越过桌面侧栏边界，同时在移动抽屉中严格贴合内容宽度。手机记录页为聊天和 Markdown 保留完整操作高度并使用纵向滚动；个人与团队记忆检索面板不再被时间线区域裁剪；极窄首页标题不再产生孤字。桌面 1280x720 的侧栏、拖动条和主区尺寸与修改前一致。没有新增依赖、API、迁移或权限变化。
