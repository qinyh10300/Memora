# Memora 最简版需求

Status: 团队共享扩展已实现，进入验收

## 1. 产品是什么

Memora 是一个由 AI 协助整理的个人与团队记忆库。

核心流程：

```text
与 Chatbot 对话
→ AI 在右侧整理 Markdown 草稿
→ 用户或 AI 修改草稿
→ 用户明确选择仅自己或团队共享
→ 在当前空间的时间线记忆库中查看和修订
```

## 2. 第一版工作空间

所有账号自动拥有个人空间，也可以创建或加入多个团队空间。侧栏始终提供：

1. 记录想法
2. 记忆库

当前空间是团队时，再显示“团队”入口。团队页展示组织名、团队号、成员昵称、角色和加入
时间。刷新页面后恢复当前 session 最近使用的空间；新注册或刚登录的用户先进入个人空间。

用户可以：

- 创建团队并成为所有者。
- 输入 12 位团队号提交加入申请；所有者批准后才成为成员。
- 复制团队号供其他已登录用户提交申请。
- 由团队所有者输入已注册邮箱直接添加成员。
- 由团队所有者批准、拒绝加入申请并移除普通成员。

首版不发送邀请或审批邮件，不邀请未注册账号，也不提供退团、角色编辑、所有权转移、
团队删除或团队号轮换。存在未保存草稿时必须先保存或清空，才能切换空间。

## 3. 记录想法页面

### 页面布局

```text
┌───────────────┬──────────────────────┬─────────────────────┐
│               │                      │ Markdown 草稿       │
│ 记录想法      │ 与 Chatbot 对话      │                     │
│ 记忆库        │                      │ # 标题              │
│               │ 用户输入消息         │ 正文……              │
│               │ AI 回复和追问        │                     │
│               │                      │ 用户可以直接修改    │
│               ├──────────────────────┤                     │
│ 当前账号      │ 输入消息       发送  │ 保存为我的记忆      │
└───────────────┴──────────────────────┴─────────────────────┘
```

### Chatbot 的作用

用户可以：

- 直接讲述一个想法。
- 在同一次记录会话中引用自己之前说过的原话。
- 让 AI 帮忙整理表达。
- 让 AI 补充结构、标题或要点。
- 让 AI 把内容改得更简洁。
- 继续补充背景，要求 AI 更新草稿。
- 询问个人记忆库中以前保存过的内容。
- 联网查询最新资料，并把有来源的摘要优化后加入草稿。
- 在 GPT、Claude 和 Gemini 三个已配置 Chat 模型之间切换。

Chatbot 每轮都能看到本次对话和右侧当前 Markdown。询问历史记忆时，服务端只向
模型提供当前用户在活动空间有权访问的记录，并为事实回答返回原始记录引用。个人空间只
包含本人记录；团队空间包含本人记录和成员主动共享的记录。AI 可以回复
而不修改草稿，也可以在回复的同时更新右侧草稿。

AI 只能修改右侧草稿，不能自动保存为正式记忆。

用户可以在消息中附加 PNG、JPEG 或 WEBP 图片。AI 可以：

- 理解截图、照片和图表中的可见内容。
- 提取图片中的文字，并按用户要求整理为 Markdown。
- 结合图片、当前对话、右侧 Markdown 和授权个人记忆回答问题。
- 只回答问题，或者在用户要求时同步修改右侧 Markdown。

图片只用于当前轮 AI 理解，不保存到记忆库；用户确认后的 Markdown 仍需显式保存。

输入框提供三个联网模式：

- **自动联网**：默认；只有消息明显需要最新或外部信息时才搜索。
- **本轮联网**：强制当前轮搜索，发送后自动恢复默认。
- **关闭联网**：只使用本次对话、右侧 Markdown 和授权个人记忆。

网页资料是不可信证据，不能覆盖权限和保存规则。AI 只能显示本轮搜索实际返回的
HTTP(S) 来源。用户要求更新草稿时，AI 应提炼内容并保留 Markdown 来源链接，而不是
把搜索摘要原样堆到右侧。搜索失败时不修改当前草稿。

### Markdown 草稿

- 草稿是纯文本 Markdown。
- 用户可以直接编辑。
- AI 可以根据用户指令修改。
- AI 修改后，用户仍可以继续手动调整。
- 用户未点击保存前，草稿不进入记忆库。
- Markdown 首个非空行派生为标题检索投影；正文仍是不可变的事实来源。

示例：

```markdown
# Memora 的早期商业模式

我认为早期应该先服务四到十人的小团队，而不是直接做个人订阅。

## 原因

- 团队共享上下文的价值更明显。
- 更容易验证是否能够减少重复沟通。
```

### 保存

个人空间右侧底部只有一个主要按钮：

> 保存为我的记忆

点击后：

- 保存当前 Markdown 原文。
- 自动记录作者和保存时间。
- 默认仅本人可见。
- 显示“已保存到我的记忆”。
- AI 不能替用户点击保存。
- 保存失败时保留草稿，不能清空内容。

团队空间在保存按钮旁显示“仅自己 / 团队共享”分段选项：

- 每条新草稿默认选择“仅自己”。
- 只有用户主动选择“团队共享”后，保存请求才使用 `WORKSPACE` 可见性。
- 切换团队、清空草稿或开始新想法后恢复默认“仅自己”。
- 已保存的本人记忆可以共享给团队或撤回为仅自己可见。

## 4. 记忆库页面

### 页面布局

```text
┌───────────────┬──────────────────────┬─────────────────────┐
│               │ 时间线记忆库         │ 记忆详情            │
│ 记录想法      │                      │                     │
│ 记忆库        │ 7 月 28 日           │ # 标题              │
│               │ ├ Markdown A         │ 正文……              │
│               │ └ Markdown B         │                     │
│               │                      │ 编辑 / AI 修改      │
│ 当前账号      │ 7 月 27 日           │ 更新当前 / 新版本   │
└───────────────┴──────────────────────┴─────────────────────┘
```

### 时间线

- 按保存时间倒序排列。
- 按日期分组。
- 每条显示标题、正文摘要和时间。
- 团队空间每条同时显示作者和“仅自己 / 团队共享”状态。
- 点击一条记忆后，在右侧显示完整 Markdown。
- 没有记忆时，引导用户回到“记录想法”。

### 检索

- 个人记忆库支持纯关键词全文检索、仅标题检索和起止日期筛选。
- 团队记忆库增加成员筛选；筛选某位成员时仍只能返回其主动共享的内容或调用者自己的记录。
- 检索使用 `POST /search` JSON body，搜索词不进入 URL 日志。
- 纯关键词检索不依赖 embedding；所有条件都在服务端授权候选上叠加。

### 查看和修改

右侧详情支持：

- 查看完整 Markdown。
- 直接修改文本。
- 点击“让 AI 修改”，输入修改要求。
- AI 把修改结果写入编辑区，由用户检查。
- 更新当前记忆。
- 保存为新版本。
- 删除记忆。

其他成员共享到团队的记忆可以阅读和引用，但不能编辑、AI 修改、修订、撤回或删除。

### 修订规则

用户修改后选择一种保存方式：

#### 更新当前记忆

- 时间线中仍然只显示当前这条记忆。
- 当前展示内容更新为最新修订。
- 后台保留旧修订，用于历史查看和恢复。
- 不允许真正删除或静默覆盖旧正文。

#### 保存为新版本

- 在时间线中创建一条新的记忆。
- 新记忆记录新的保存时间。
- 新记忆与原始记忆建立版本关系。
- 原始记忆继续作为独立时间点保留。

两种方式的区别：

- “更新当前记忆”不在时间线增加新条目。
- “保存为新版本”会在时间线增加新条目。
- 两种方式都不会丢失旧正文。

版本历史中：

- 默认展示最新版本。
- 用户可以查看之前版本。

## 5. AI 修改规则

- AI 只处理用户当前有权访问的草稿或记忆。
- AI 修改前必须由用户明确提出要求。
- AI 修改结果先进入编辑区，不自动保存。
- 用户始终可以手动覆盖 AI 的结果。
- AI 不得编造用户没有表达过的事实。
- 使用网页时必须展示实际使用的可点击来源，不得编造来源 URL。
- 不确定时，AI 应追问而不是自行补全。

## 6. 隐私规则

- 点击“保存为我的记忆”后，内容默认仅本人可见。
- 团队空间的所有新记忆也默认仅本人可见，只有显式选择才共享。
- 团队成员只能读取当前团队内其他成员的 `WORKSPACE` 记忆。
- 其他成员的 `PRIVATE` 记忆不得出现在列表、详情、检索候选、AI 提示词、引用、报告、
  受保护资产授权或正文日志中。
- 只有作者可以分享、撤回、修订或删除自己的记忆；团队所有者没有读取成员私有记忆的特权。
- 待审核申请不是 membership，不能读取团队列表、检索、AI 上下文或受保护资产。
- 所有者移除成员后，该成员的活动 session 回到个人空间并立即失去团队访问权。
- 个人空间拒绝 `WORKSPACE` 可见性。
- 其他用户不能读取个人私有记忆。
- AI 服务失败不能导致草稿或已保存记忆丢失。
- 删除后，正文和向量都不能继续被检索。

## 7. 第一版不做

- PDF、普通文件、语音和视频上传。
- 图片原图的长期保存和跨会话恢复。
- 复杂组织层级、角色管理、所有权转移和团队共同编辑。
- 外部邮件邀请和邀请未注册账号。
- 多个聊天窗口。
- 独立分析页面。
- 自动报告。
- 自动标签和知识图谱。

## 8. 验收标准

第一版完成后，用户应该可以：

1. 通过对话让 AI 形成一篇 Markdown 草稿。
2. 手动或通过 AI 修改草稿。
3. 点击按钮保存为个人记忆。
4. 在按时间排列的记忆库中找到它。
5. 点击记忆，在右侧查看完整内容。
6. 选择“更新当前记忆”，时间线不新增条目，但可以查看旧修订。
7. 选择“保存为新版本”，时间线出现一个新的关联条目。
8. 查看旧版本，确认任何保存方式都没有丢失历史正文。
9. 选择本轮联网，把带来源的优化结果加入右侧，并确认未点击保存前记忆库不新增记录。
10. 创建团队，查看团队号和成员目录，并在个人与团队空间之间切换。
11. 使用团队号提交申请，在所有者批准前不能进入团队；所有者也可以按已注册邮箱直接添加
    成员，普通成员不能执行审核或成员管理。
12. 在团队保存时默认保持私人，主动选择后共享；其他成员能看到作者但不能编辑。
13. 验证另一成员的私有记忆无法通过列表、ID、检索、AI 或引用读取，撤回共享后也立即失效。
14. 所有者可以拒绝申请、移除普通成员，且被移除成员的 session 回到个人空间。
15. 在个人记忆库按全文、标题和日期检索；在团队记忆库增加成员筛选。
16. 在 GPT、Claude 和 Gemini 之间切换，并确认请求携带所选模型 ID。

## 9. 已确认决定

1. 用户修改已保存记忆时，可以选择“更新当前记忆”或“保存为新版本”。
2. “更新当前记忆”在产品界面上表现为覆盖，但后台仍保留不可变修订历史。
3. 团队空间支持选择性共享，但所有新记忆仍默认私人。
4. 团队号只用于提交待审核申请，并只在请求正文中传输；成员均可查看，申请请求需要限流。
5. 邮箱添加只面向已注册账号且仅限团队所有者，不产生外部邮件或待处理邀请。
6. 只有 `OWNER` 可以审核申请和移除普通成员；不能移除团队所有者。
