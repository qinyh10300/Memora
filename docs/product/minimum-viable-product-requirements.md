# Memora 最简版需求

Status: 已批准，待实现

## 1. 产品是什么

Memora 是一个由 AI 协助整理的个人记忆库。

核心流程：

```text
与 Chatbot 对话
→ AI 在右侧整理 Markdown 草稿
→ 用户或 AI 修改草稿
→ 用户点击“保存为我的记忆”
→ 在时间线记忆库中查看和修订
```

## 2. 第一版只做两个页面

左侧导航只保留：

1. 记录想法
2. 记忆库

暂时不做分析、成员管理、多空间和多个聊天窗口。

## 3. 记录想法页面

### 页面布局

```text
┌───────────────┬──────────────────────┬─────────────────────┐
│               │                      │ Markdown 草稿       │
│ 记录想法      │ 与 Chatbot 对话      │                     │
│ 记忆库        │                      │ # 标题              │
│               │ 用户输入消息         │ 正文……              │
│               │ AI 回复和追问        │                     │
│               │                      │ 用户可以直接修改    │
│               ├──────────────────────┤                     │
│ 当前账号      │ 输入消息       发送  │ 保存为我的记忆      │
└───────────────┴──────────────────────┴─────────────────────┘
```

### Chatbot 的作用

用户可以：

- 直接讲述一个想法。
- 让 AI 帮忙整理表达。
- 让 AI 补充结构、标题或要点。
- 让 AI 把内容改得更简洁。
- 继续补充背景，要求 AI 更新草稿。

AI 只能修改右侧草稿，不能自动保存为正式记忆。

### Markdown 草稿

- 草稿是纯文本 Markdown。
- 用户可以直接编辑。
- AI 可以根据用户指令修改。
- AI 修改后，用户仍可以继续手动调整。
- 用户未点击保存前，草稿不进入记忆库。
- Markdown 第一行可以作为标题，但第一版不增加复杂字段。

示例：

```markdown
# Memora 的早期商业模式

我认为早期应该先服务四到十人的小团队，而不是直接做个人订阅。

## 原因

- 团队共享上下文的价值更明显。
- 更容易验证是否能够减少重复沟通。
```

### 保存

右侧底部只有一个主要按钮：

> 保存为我的记忆

点击后：

- 保存当前 Markdown 原文。
- 自动记录作者和保存时间。
- 默认仅本人可见。
- 显示“已保存到我的记忆”。
- AI 不能替用户点击保存。
- 保存失败时保留草稿，不能清空内容。

## 4. 记忆库页面

### 页面布局

```text
┌───────────────┬──────────────────────┬─────────────────────┐
│               │ 时间线记忆库         │ 记忆详情            │
│ 记录想法      │                      │                     │
│ 记忆库        │ 7 月 28 日           │ # 标题              │
│               │ ├ Markdown A         │ 正文……              │
│               │ └ Markdown B         │                     │
│               │                      │ 编辑 / AI 修改      │
│ 当前账号      │ 7 月 27 日           │ 更新当前 / 新版本   │
└───────────────┴──────────────────────┴─────────────────────┘
```

### 时间线

- 按保存时间倒序排列。
- 按日期分组。
- 每条显示标题、正文摘要和时间。
- 点击一条记忆后，在右侧显示完整 Markdown。
- 没有记忆时，引导用户回到“记录想法”。

### 查看和修改

右侧详情支持：

- 查看完整 Markdown。
- 直接修改文本。
- 点击“让 AI 修改”，输入修改要求。
- AI 把修改结果写入编辑区，由用户检查。
- 更新当前记忆。
- 保存为新版本。
- 删除记忆。

### 修订规则

用户修改后选择一种保存方式：

#### 更新当前记忆

- 时间线中仍然只显示当前这条记忆。
- 当前展示内容更新为最新修订。
- 后台保留旧修订，用于历史查看和恢复。
- 不允许真正删除或静默覆盖旧正文。

#### 保存为新版本

- 在时间线中创建一条新的记忆。
- 新记忆记录新的保存时间。
- 新记忆与原始记忆建立版本关系。
- 原始记忆继续作为独立时间点保留。

两种方式的区别：

- “更新当前记忆”不在时间线增加新条目。
- “保存为新版本”会在时间线增加新条目。
- 两种方式都不会丢失旧正文。

版本历史中：

- 默认展示最新版本。
- 用户可以查看之前版本。

## 5. AI 修改规则

- AI 只处理用户当前有权访问的草稿或记忆。
- AI 修改前必须由用户明确提出要求。
- AI 修改结果先进入编辑区，不自动保存。
- 用户始终可以手动覆盖 AI 的结果。
- AI 不得编造用户没有表达过的事实。
- 不确定时，AI 应追问而不是自行补全。

## 6. 隐私规则

- 点击“保存为我的记忆”后，内容默认仅本人可见。
- 第一版所有新记忆都只保存给本人。
- 第一版不显示团队共享入口。
- 其他用户不能读取个人私有记忆。
- AI 服务失败不能导致草稿或已保存记忆丢失。
- 删除后，正文和向量都不能继续被检索。

## 7. 第一版不做

- 文件、图片和语音上传。
- 团队组织架构。
- 团队共享记忆。
- 多空间和团队创建。
- 多个聊天窗口。
- 独立分析页面。
- 自动报告。
- 自动标签和知识图谱。

## 8. 验收标准

第一版完成后，用户应该可以：

1. 通过对话让 AI 形成一篇 Markdown 草稿。
2. 手动或通过 AI 修改草稿。
3. 点击按钮保存为个人记忆。
4. 在按时间排列的记忆库中找到它。
5. 点击记忆，在右侧查看完整内容。
6. 选择“更新当前记忆”，时间线不新增条目，但可以查看旧修订。
7. 选择“保存为新版本”，时间线出现一个新的关联条目。
8. 查看旧版本，确认任何保存方式都没有丢失历史正文。

## 9. 已确认决定

1. 用户修改已保存记忆时，可以选择“更新当前记忆”或“保存为新版本”。
2. “更新当前记忆”在产品界面上表现为覆盖，但后台仍保留不可变修订历史。
3. 第一版只保存个人记忆，不提供团队共享入口。
