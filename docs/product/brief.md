# Memora Product Brief

Status: Approved baseline with personal Markdown MVP simplification

Version: next MVP — personal Markdown capture and timeline

Last updated: 2026-07-26

## One-line proposition

Memora 是一个由 AI 协助整理的个人记忆库：用户通过对话形成可编辑的 Markdown，把确认后的内容保存为带时间的个人记忆，并在时间线中查看和修订。

## Problem

个人目前将想法分散记录在 GitHub、文档或其他零散位置，容易漏记，之后需要花大量时间翻找，也难以看出自己的观点如何随时间变化。

团队成员的想法分散在各自文档中。为了理解彼此的背景、进展和观点，成员需要逐篇阅读或反复开会，无法直接获得经过授权且可追溯的共享上下文。

## Target users

### Primary v0.1 user

愿意持续记录工作想法、需要回顾个人判断，并在一个四人小团队中选择性共享上下文的知识工作者。

### Future users

- 需要跨时间回顾决策和观点演进的个人用户。
- 需要异步共享进展、减少重复同步的小团队。
- 需要组织级权限、审计和私有模型部署的企业用户。

未来用户不构成 v0.1 的交付承诺。

## Jobs to be done

- 当一个想法出现时，我希望在很短时间内记录下来，以免之后遗忘。
- 当我记不清过去的观点时，我希望通过含时间和原文来源的回答快速找回。
- 当我怀疑自己以前有过类似想法时，我希望找到相似记录及其出现时间。
- 当我回顾一段时间时，我希望得到观点变化报告，并能检查报告依据。
- 当我需要了解同事或团队进展时，我希望只基于成员主动共享的记录获得总结。

## Product principles

1. **Capture before enrichment**：先保证记录可靠，AI 处理失败不能导致想法丢失。
2. **Private by default**：新记录默认只属于作者，分享必须是显式动作。
3. **Evidence over fluency**：回答是否有依据比语言是否流畅更重要。
4. **Temporal integrity**：历史不被静默改写，观点变化通过追加记录呈现。
5. **Unknown is valid**：证据不足时说不知道，不用推测填补空白。
6. **Simple core, replaceable AI**：产品核心不绑定单一模型或供应商。
7. **Conversation as the surface**：Web 优先呈现一个对话入口，记录、回顾和低频管理动作在对话中完成；内部权限参数不直接变成多组用户表单。

## v0.1 scope

### Accounts and workspace

- 一个测试工作区。
- 四个预置账号，通过同一个公网网址访问。
- 不提供公开注册、邀请、找回密码或企业身份集成。

### Memory capture

- 用户创建一条纯文本想法。
- 系统自动记录作者和创建时间。
- 新记录默认私有；作者可以主动共享给整个测试工作区。
- 正文不原地修改。用户通过新建补充记录修正或延展历史，可关联原记录。
- 作者可以删除记录。删除后正文和 embedding 不再可检索。

### Browse and retrieval

- 用户浏览自己的记录以及其他成员共享给工作区的记录。
- 支持按作者、时间范围和可见性缩小范围。
- 支持关键词与语义相似检索。

### AI assistant

- 登录后默认进入单一 Chatbot 界面，不再用侧边导航拆分记录、搜索、问答和报告。
- 普通陈述先作为待保存草稿，助手必须追问“仅自己”或“共享团队”；用户明确选择前不写入。
- 对当前用户有权访问的记录进行问答。
- 支持个人、指定同事和整个工作区范围，但不得越过共享边界。
- 支持时间范围和对话上下文。
- 事实性结论引用原始记录、作者和时间，并提供回到原记录的入口。
- 对“这个”“类似”“这段时间”等无法可靠解析的指代主动追问。
- 证据不足时明确说明信息缺失。
- 分享、取消共享、补充和删除等低频动作可用自然语言命令完成；删除仍需二次确认。

### Reports

- 按需生成个人或团队时间段报告。
- 个人变化报告应区分阶段、延续、变化、矛盾和证据缺口。
- 同事报告只能使用该同事主动共享的内容。
- 团队报告标明信息来自哪些成员和记录，不把 AI 推断表述为事实。
- v0.1 不提供定时生成或主动推送。

## v0.2 approved extension

v0.2 保留 v0.1 的记录、授权检索、引用和报告语义，将单一临时对话页升级为可以持续使用的工作台。

### Spaces and membership

- 每个用户自动拥有一个个人空间，并可以加入多个团队空间。
- 用户可以创建新的团队空间；第一版只有创建者 membership，不包含邀请、移除成员或所有权转移。
- 空间是 Chat、memory、检索、报告和成员列表的硬隔离边界，默认不允许跨空间检索。
- 用户只能看到和切换自己存在 membership 的空间。
- 对外界面统一使用“空间”；后端继续使用 workspace 领域术语。

### Persistent conversations

- 每个空间可以创建多个 conversation，并在刷新或重新登录后恢复。
- conversation 及其消息默认只属于创建用户，不因使用团队共享证据而自动共享。
- conversation 只是交互上下文，不是 memory 文件夹或权限边界；同一授权 memory 可以被多个 conversation 引用。
- 用户可以重命名和归档自己的 conversation，不能读取其他成员的 conversation。
- 普通陈述和授权问答都写入当前 conversation；记录仍必须在选择可见范围后才创建。

### Memory library

- 工作台提供统一记忆库，并区分“我的记忆”和“团队共享”。
- “我的记忆”展示当前用户在当前空间的私有及已共享记录。
- “团队共享”只展示当前空间成员主动设为 `WORKSPACE` 的记录，不暗示系统能读取成员私有内容。
- 点击记录或 AI 回答引用时，可以查看当前仍有权访问的原文、作者、时间、可见范围和补充关系。
- 分享、取消共享、补充和删除仍只能由作者执行，权限由服务端验证。

### Workspace shell

- 桌面端使用可收起侧栏承载空间切换、新建 conversation、记忆库入口和 conversation 历史。
- 移动端使用覆盖式侧栏和原文抽屉，保持主聊天输入可用。
- 切换空间会清除未提交草稿和待确认状态，随后重新加载该空间的 conversation、成员和授权 memory。
- Chat 输入仍统一承载记录与提问，不增加必须手动选择的“记录/问答模式”开关。

## v0.3 workspace-first extension

### Product correction

v0.2 解决了多空间和 conversation 持久化，但左栏仍然以“对话历史”为主，使 Memora 看起来像通用 Chatbot。v0.3 把空间中的真实任务提升为一级导航：

- 记录记忆
- 记忆问答
- 团队记忆
- 分析
- 成员与权限

conversation 历史继续存在，但只作为恢复工作上下文的辅助入口。“记录记忆”和“记忆问答”仍复用统一 Chat 能力，不引入两套数据入口。

### Language and permission rules

- 纯文本入口称为“记录记忆”，不称为“上传记忆”；只有真正支持文件或批量导入后才能使用“上传”。
- “团队记忆”只代表成员主动共享到当前空间的 `WORKSPACE` 记录，不代表管理员或成员可以浏览别人的私有记录。
- “成员与权限”在本阶段是只读目录，用于解释组织角色和共享边界，不提供尚未实现的邀请、删除或授权按钮。
- 分析必须显式展示范围、时间和证据；证据不足时继续返回不知道，而不是用仪表盘制造确定性。

## Approved personal Markdown MVP simplification

本节是当前已经实现并进入验收的产品范围。前面的 v0.1–v0.3 章节保留已完成的需求演进记录；如果界面范围发生冲突，以本节为准。已有团队、多空间、conversation 和报告后台能力先保留，不因界面简化而删除数据或接口。

### Visible product surface

- 一级导航只保留“记录想法”和“记忆库”。
- “记录想法”由中间 Chatbot 和右侧 Markdown 草稿组成。
- 用户可以直接编辑草稿，也可以通过对话要求 AI 修改草稿。
- AI 只能更新未保存的编辑区，不能代替用户执行保存。
- 用户点击“保存为我的记忆”后，系统保存当前 Markdown、作者和时间。
- 第一版所有新记忆均为个人私有记忆，不显示团队共享入口。
- “记忆库”按日期和时间倒序编排；点击条目后在右侧打开完整 Markdown。

### Revision choices

已保存记忆的修改提供两种用户选择，两者都不真正原地覆盖历史正文：

1. **更新当前记忆**：时间线不新增条目，当前逻辑记忆展示最新修订；后台保留旧修订，支持历史查看和恢复。
2. **保存为新版本**：在时间线创建一条新的关联记忆，使用新的保存时间；原始记忆继续作为独立时间点存在。

手动编辑和 AI 修改都先进入编辑区。只有用户点击相应保存操作后才写入正式记忆。

### Temporarily hidden

- 团队共享和团队记忆。
- 空间切换、创建团队和成员权限。
- 多 conversation 及聊天历史导航。
- 独立分析页和报告配置页。

完整交互和验收以 `docs/product/minimum-viable-product-requirements.md` 为准。

## Representative interactions

1. 把我刚才的想法整理成一篇 Markdown，但不要改变原意。
2. 把这篇草稿改得更简洁，并保留关键理由。
3. 之前我对这个商业模式的看法是什么？
4. 我以前有没有出现过类似想法？分别是什么时候？
5. 更新当前记忆，但不要在时间线中创建新条目。
6. 把这次变化保存为新版本，保留原来的时间点。

这些交互将成为草稿修改、版本行为和个人检索质量评测集的起点。

## Non-goals for v0.1

- 文件、图片、音频、视频、网页或第三方知识库导入。
- 移动端原生应用和浏览器插件。
- 公开注册、复杂组织层级、细粒度群组分享和企业 SSO。
- 自动标签、知识图谱或完全自动化的主题体系。
- 定时周报、消息推送和会议系统集成。
- 用 AI 推断用户心理、绩效或未明确记录的经历。
- 微服务、Kubernetes、多区域高可用或大规模商业计费系统。
- 本地模型部署；v0.1 只保留可替换接口。

## Non-goals for v0.2

- 共享 conversation、公开 conversation 链接或团队共同编辑 conversation。
- 跨空间统一搜索、跨空间报告或把一个 memory 同时发布到多个空间。
- 团队邀请、成员移除、复杂角色、企业 SSO 和组织层级树。
- 删除空间、转移所有权、细粒度群组或点对点分享。

## Privacy and AI processing

- 用户记录可能被发送到配置的外部 AI 中转服务，用于 embedding、问答和报告生成。
- 产品测试前必须向四位用户明确披露该处理方式并获得同意。
- 发送给模型的内容必须先经过服务端权限过滤，只包含完成当前请求所需的最小记录集合。
- API Key 仅保存在服务器或开发者本机的未跟踪环境变量中，不进入客户端、不提交到 Git。
- 在引入企业用户前，需要重新评估供应商条款、数据保留、日志、跨境处理和本地模型方案。

## Validation experiment

四位测试者连续使用两周，每人至少保存十五条真实 Markdown 记忆，并完成 AI 整理、手动修改、个人找回、更新当前记忆和保存为新版本。

### Primary v0.1 signals

- **持续记录**：四位用户中至少三位达到十五条真实记录。
- **草稿可控**：AI 修改只进入编辑区，用户确认前不自动保存；测试者认为修改没有改变核心原意。
- **检索可信**：测试者认为至少 80% 的评测回答找到了正确或有用的记录。
- **引用完整**：所有事实性回答都附有当前用户可访问的来源；自动化越权测试为零泄漏。
- **修订可信**：更新当前记忆和保存为新版本的时间线行为符合预期，旧正文始终可以恢复。
- **记录摩擦低**：测试者能在约十五秒内完成一条纯文本记录。

团队共享和“减少会议时间”不属于这次个人 MVP 的验证范围。

## Risks and assumptions

- 用户可能不愿额外打开一个 Web 产品记录想法，记录入口的摩擦是首要采用风险。
- AI 整理可能在语言变得流畅的同时改变原意，用户确认和可恢复修订是必要边界。
- “更新当前记忆”和“保存为新版本”的差异可能不够直观，需要通过时间线行为验证。
- 语义相似不等于观点相同，结果必须允许用户检查原文。
- 外部中转服务的模型、接口稳定性和数据处理方式可能变化，必须隔离供应商依赖。
- “可扩展到其他产品”暂时只通过清晰模块边界实现，不提前构建通用平台。
