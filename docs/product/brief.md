# Memora Product Brief

Status: Approved baseline with personal and team Markdown workspaces

Version: next MVP — personal and team Markdown memory

Last updated: 2026-08-06

## One-line proposition

Memora 是一个由 AI 协助整理的个人与团队记忆库：用户通过对话形成可编辑的 Markdown，把确认后的内容保存为带时间的私人或团队共享记忆，并在授权范围内查看和修订。

## Problem

个人目前将想法分散记录在 GitHub、文档或其他零散位置，容易漏记，之后需要花大量时间翻找，也难以看出自己的观点如何随时间变化。

团队成员的想法分散在各自文档中。为了理解彼此的背景、进展和观点，成员需要逐篇阅读或反复开会，无法直接获得经过授权且可追溯的共享上下文。

## Target users

### Primary v0.1 user

愿意持续记录工作想法、需要回顾个人判断，并在一个四人小团队中选择性共享上下文的知识工作者。

### Future users

- 需要跨时间回顾决策和观点演进的个人用户。
- 需要异步共享进展、减少重复同步的小团队。
- 需要组织级权限、审计和私有模型部署的企业用户。

未来用户不构成 v0.1 的交付承诺。

## Jobs to be done

- 当一个想法出现时，我希望在很短时间内记录下来，以免之后遗忘。
- 当我记不清过去的观点时，我希望通过含时间和原文来源的回答快速找回。
- 当我怀疑自己以前有过类似想法时，我希望找到相似记录及其出现时间。
- 当我回顾一段时间时，我希望得到观点变化报告，并能检查报告依据。
- 当我需要了解同事或团队进展时，我希望只基于成员主动共享的记录获得总结。

## Product principles

1. **Capture before enrichment**：先保证记录可靠，AI 处理失败不能导致想法丢失。
2. **Private by default**：新记录默认只属于作者，分享必须是显式动作。
3. **Evidence over fluency**：回答是否有依据比语言是否流畅更重要。
4. **Temporal integrity**：历史不被静默改写，观点变化通过追加记录呈现。
5. **Unknown is valid**：证据不足时说不知道，不用推测填补空白。
6. **Simple core, replaceable AI**：产品核心不绑定单一模型或供应商。
7. **Conversation as the surface**：Web 优先呈现一个对话入口，记录、回顾和低频管理动作在对话中完成；内部权限参数不直接变成多组用户表单。

## v0.1 scope

### Accounts and workspace

- 支持使用邮箱账号和密码公开注册，也支持服务端邮箱验证码注册与登录；每个新账号自动获得一个只属于自己的个人空间。
- 四个预置账号和测试工作区继续用于开发验收，公开注册用户不会自动加入该工作区。
- 暂不提供邀请、找回密码或企业身份集成。

### Memory capture

- 用户创建一条纯文本想法。
- 系统自动记录作者和创建时间。
- 新记录默认私有；作者可以主动共享给整个测试工作区。
- 正文不原地修改。用户通过新建补充记录修正或延展历史，可关联原记录。
- 作者可以删除记录。删除后正文和 embedding 不再可检索。

### Browse and retrieval

- 用户浏览自己的记录以及其他成员共享给工作区的记录。
- 支持按作者、时间范围和可见性缩小范围。
- 支持关键词与语义相似检索。

### AI assistant

- 登录后默认进入单一 Chatbot 界面，不再用侧边导航拆分记录、搜索、问答和报告。
- 普通陈述先作为待保存草稿，助手必须追问“仅自己”或“共享团队”；用户明确选择前不写入。
- 对当前用户有权访问的记录进行问答。
- 支持个人、指定同事和整个工作区范围，但不得越过共享边界。
- 支持时间范围和对话上下文。
- 事实性结论引用原始记录、作者和时间，并提供回到原记录的入口。
- 对“这个”“类似”“这段时间”等无法可靠解析的指代主动追问。
- 证据不足时明确说明信息缺失。
- 分享、取消共享、补充和删除等低频动作可用自然语言命令完成；删除仍需二次确认。

### Reports

- 按需生成个人或团队时间段报告。
- 个人变化报告应区分阶段、延续、变化、矛盾和证据缺口。
- 同事报告只能使用该同事主动共享的内容。
- 团队报告标明信息来自哪些成员和记录，不把 AI 推断表述为事实。
- v0.1 不提供定时生成或主动推送。

## v0.2 approved extension

v0.2 保留 v0.1 的记录、授权检索、引用和报告语义，将单一临时对话页升级为可以持续使用的工作台。

### Spaces and membership

- 每个用户自动拥有一个个人空间，并可以加入多个团队空间。
- 用户可以创建新的团队空间；第一版只有创建者 membership，不包含邀请、移除成员或所有权转移。
- 空间是 Chat、memory、检索、报告和成员列表的硬隔离边界，默认不允许跨空间检索。
- 用户只能看到和切换自己存在 membership 的空间。
- 对外界面统一使用“空间”；后端继续使用 workspace 领域术语。

### Persistent conversations

- 每个空间可以创建多个 conversation，并在刷新或重新登录后恢复。
- conversation 及其消息默认只属于创建用户，不因使用团队共享证据而自动共享。
- conversation 只是交互上下文，不是 memory 文件夹或权限边界；同一授权 memory 可以被多个 conversation 引用。
- 用户可以重命名和归档自己的 conversation，不能读取其他成员的 conversation。
- 普通陈述和授权问答都写入当前 conversation；记录仍必须在选择可见范围后才创建。

### Memory library

- 工作台提供统一记忆库，并区分“我的记忆”和“团队共享”。
- “我的记忆”展示当前用户在当前空间的私有及已共享记录。
- “团队共享”只展示当前空间成员主动设为 `WORKSPACE` 的记录，不暗示系统能读取成员私有内容。
- 点击记录或 AI 回答引用时，可以查看当前仍有权访问的原文、作者、时间、可见范围和补充关系。
- 分享、取消共享、补充和删除仍只能由作者执行，权限由服务端验证。

### Workspace shell

- 桌面端使用可收起侧栏承载空间切换、新建 conversation、记忆库入口和 conversation 历史。
- 移动端使用覆盖式侧栏和原文抽屉，保持主聊天输入可用。
- 切换空间会清除未提交草稿和待确认状态，随后重新加载该空间的 conversation、成员和授权 memory。
- Chat 输入仍统一承载记录与提问，不增加必须手动选择的“记录/问答模式”开关。

## v0.3 workspace-first extension

### Product correction

v0.2 解决了多空间和 conversation 持久化，但左栏仍然以“对话历史”为主，使 Memora 看起来像通用 Chatbot。v0.3 把空间中的真实任务提升为一级导航：

- 记录记忆
- 记忆问答
- 团队记忆
- 分析
- 成员与权限

conversation 历史继续存在，但只作为恢复工作上下文的辅助入口。“记录记忆”和“记忆问答”仍复用统一 Chat 能力，不引入两套数据入口。

### Language and permission rules

- 纯文本入口称为“记录记忆”，不称为“上传记忆”；只有真正支持文件或批量导入后才能使用“上传”。
- “团队记忆”只代表成员主动共享到当前空间的 `WORKSPACE` 记录，不代表管理员或成员可以浏览别人的私有记录。
- “成员与权限”在本阶段是只读目录，用于解释组织角色和共享边界，不提供尚未实现的邀请、删除或授权按钮。
- 分析必须显式展示范围、时间和证据；证据不足时继续返回不知道，而不是用仪表盘制造确定性。

## Approved Markdown workspace MVP

本节是当前已经实现并进入验收的产品范围。前面的 v0.1–v0.3 章节保留需求演进记录；
如果界面范围发生冲突，以本节和 ADR 0004 为准。当前恢复个人/团队空间切换与选择性共享，
多 conversation 和报告后台能力继续保留但不进入当前一级界面。

### Visible product surface

- 未登录访客首先看到 Memora 公开首页；“登录”与“快速开始”分别打开邮箱密码登录和注册
  表单。已有有效会话访问同一地址时直接进入工作台，不重复显示首页。
- 注册会创建独立个人空间并自动登录；公开注册用户不会自动加入测试团队或获得其他用户
  数据的访问权。新登录先进入个人空间，之后刷新或重新打开页面时恢复该 session 最近使用
  的个人或团队空间。
- 后端同时保留密码认证和邮箱验证码认证。验证码按注册与登录用途隔离、短时有效且只能使用
  一次；服务端只保存摘要。四个开发 seed 账号继续支持原密码登录。
- 所有用户都可以创建团队，或用 12 位团队号提交加入申请；团队所有者审核通过后才创建
  membership。团队所有者还可以按已注册邮箱直接添加成员，并可移除普通成员。首版不发送
  邀请或审批邮件，也不为未注册邮箱创建待处理邀请。
- 一级导航保留“记录想法”和“记忆库”；当前空间为团队时增加“团队”入口，用于查看组织名、
  团队号、成员昵称、角色和加入时间。
- 侧栏空间切换器只列出当前用户已有 membership 的个人和团队空间。存在未保存草稿或正在
  保存/生成时阻止切换，避免内容写入错误空间。
- “记录想法”以 Chatbot 为主。新对话先展示居中的标题和输入框，首条消息后输入框移动到
  底部；右侧面板默认关闭，用户需要时再打开 Markdown 草稿或云知识库。
- 用户可以直接编辑草稿，也可以通过对话要求 AI 修改草稿。
- Chatbot 每轮看到本次 capture 对话和右侧当前 Markdown；用户要求恢复原话时，
  原始输入来自会话历史，而不是让模型从已改写草稿中猜测。
- Chatbot 可以基于服务端授权筛选的当前空间记忆回答问题；个人空间只含本人记录，团队空间
  只含本人记录和成员主动共享的记录，事实性回答继续返回原记录引用。
- 用户可以在当前消息粘贴或选择 PNG、JPEG 或 WEBP 图片。图片会保存为受保护资产，
  并以 Markdown 图片语法插入草稿；用户保存记忆后，图片随 Markdown 长期可见。
  当前轮仍会把图片内容发送给支持视觉的 Chatbot，用于理解图片、提取文字、回答问题
  或更新 Markdown。
- 用户可以在当前消息附加 PDF。PDF 上传为受保护资产后进入异步解析队列，界面显示排队、
  文本抽取、按需 OCR、完成或失败状态，并允许取消或重试。只有解析完成且仍通过当前账号与
  空间授权的页级片段可以进入 Chatbot；生成的草稿显示可打开的文件名与页码来源。
- PDF 不作为普通附件嵌入正式 Markdown。只有用户明确确认才保存 Markdown 正文；正文可以
  保存服务端验证过的页级引用。被正式记忆引用的 PDF 继续作为受保护来源保留，删除资产或
  失去共享权限后不得再读取原文、chunk、向量或引用目标。
- 输入框提供“自动联网”“本轮联网”“关闭联网”。自动模式只在用户明确需要最新或
  外部信息时搜索；本轮联网发送后恢复自动；关闭联网时只使用对话和授权个人记忆。
- 联网结果先由 AI 提炼，再按用户要求回答或更新右侧 Markdown。实际使用的网页来源
  必须可点击；写入草稿时保留 Markdown 来源链接，搜索失败时不覆盖现有草稿。
- AI 只能更新未保存的编辑区，不能代替用户执行保存。
- 用户点击保存后，系统保存当前 Markdown、作者和时间。个人空间只能保存为 `PRIVATE`；
  团队空间在“仅自己”和“团队共享”之间显式选择，默认仍为“仅自己”。
- “记忆库”按日期和时间倒序编排，并提供纯关键词、标题和时间范围检索；团队空间额外支持
  成员筛选。团队空间展示本人私有记忆与所有成员主动共享的记忆，每条均标明作者和可见
  范围。其他成员的共享记忆只读，修改、撤回和删除仍由作者控制。
- Chatbot 可以在模型注册表配置的 GPT、Claude 和 Gemini 之间切换；模型选择不改变
  workspace 授权、显式保存或引用规则。
- 桌面侧栏可以连续拖动，并在接近最小宽度时吸附为只显示 Memora 标志和展开按钮的窄栏；
  对话 / Markdown 以及记忆列表 / 详情分隔条可以把任一侧吸附隐藏，并从边缘恢复。布局偏好
  在当前浏览器保存；移动端继续使用完整抽屉和纵向工作流。
- 侧栏账号区域打开个人设置，不增加一级导航。用户可以修改头像和昵称，也可以在验证
  当前密码后更新密码；改密后当前设备保持登录，其他活动会话退出。

### Revision choices

已保存记忆的修改提供两种用户选择，两者都不真正原地覆盖历史正文：

1. **更新当前记忆**：时间线不新增条目，当前逻辑记忆展示最新修订；后台保留旧修订，支持历史查看和恢复。
2. **保存为新版本**：在时间线创建一条新的关联记忆，使用新的保存时间；原始记忆继续作为独立时间点存在。

手动编辑和 AI 修改都先进入编辑区。只有用户点击相应保存操作后才写入正式记忆。

### Temporarily hidden

- 多 conversation 及聊天历史导航。
- 独立分析页和报告配置页。
- 主动退团、角色修改、所有权转移、团队删除和团队号轮换。
- 向未注册邮箱发出待处理邀请、外部邮件通知和企业身份集成。
- 共享 conversation、评论与多人共同编辑。

完整交互和验收以 `docs/product/minimum-viable-product-requirements.md` 为准。

## Approved knowledge workspace and subscription extension

本节由 2026-08-07 的产品要求批准，是当前界面的增量范围。它覆盖前文“多 conversation 及
聊天历史导航暂时隐藏”、知识图谱和商业计费不进入当前版本的旧决定，但不改变默认私有、
workspace 隔离、显式共享和事实引用规则。

### Subscription and credits

- 每个注册用户拥有 Plus、Pro 或 Ultra 订阅和独立 credits 余额。Plus 默认每周期 2,000，
  Pro 10,000，Ultra 50,000 credits；套餐数字属于产品配置，不构成支付供应商账单。
- 用户可以在账号区查看当前套餐、周期余额、已用额度和非正文账本，并执行内部套餐升级。
  在接入明确的支付供应商前，产品不得展示银行卡扣款、自动续费或退款已经完成。
- 成功调用聊天模型的草稿对话消耗 10 credits；禁用模型、调用失败或本地降级不扣费。
  credits 只控制付费计算资源，不改变用户能看到哪些 workspace、记忆、文档或图。

### Knowledge diagrams

- 一级导航增加“知识框图”。用户可以从当前有权访问的记忆中选择节点，创建思维导图或
  流程图，拖动节点、建立显式连线、保存并重新打开。
- 图绑定当前 workspace 和创建者。私有图只有创建者可见；共享图对当前空间成员可见，
  但只能引用仍为 `WORKSPACE` 的同空间记忆。共享图不得以节点标签、缓存正文或失效快照
  暴露私有或已撤回的记忆。
- 图用于表达用户确认的关系，不自动把语义相似当成事实关系，也不引入第二个图数据库。

### Research, knowledge base, and history

- 一级导航增加“深度调研”和“云知识库”。深度调研复用受控 Agent、联网来源、授权记忆和
  文档页码引用；AI 仍只能修改未保存草稿，不能代替用户确认正式记忆。
- 云知识库聚合当前授权的记忆与这些记忆引用的受保护文档来源。它不是通用网盘，不提供
  无鉴权静态 URL，也不显示未被当前用户授权访问的团队文件。
- 助手更新草稿或完成保存后显示结果卡。用户可以查看右侧草稿、进入完整云知识库，或把
  云知识库停靠到聊天右侧；停靠面板可调宽、切换和关闭，不改变 workspace 或 memory 权限。
- 侧栏恢复当前用户在当前 workspace 的 conversation 历史，支持新建、恢复和归档。
  conversation 继续仅属于创建者，不因为在团队空间中使用而自动共享。

### Personal and team spaces

- Web 只提供个人与团队空间，不再展示家庭分组或创建家庭入口。
- 数据库中的 `FAMILY` 类型暂时保留为历史兼容边界，不新增家庭入口，也不改变既有记录的
  工作区归属或可见性规则。

## Approved AI Native visuals and team intelligence extension

本扩展于 2026-08-07 批准，详细需求以
`docs/product/ai-native-workspace-requirements.md` 为准，并继续服从默认私有、来源授权、不可变
记忆和证据优先原则。

- “科研绘图”从授权记忆或提示词生成可编辑的思维导图、流程图、时间线，以及由外部图片模型
  生成的科研视觉。文字密集型结构图使用受校验的结构数据，不依赖图片模型绘制文字。
- 首批生图产品选项为 GPT Image 2、Nano Banana、Nano Banana 2、Nano Banana Pro；支持图片
  比例、1–4 张、科研风格增强、水印处理和输出语言。展示名称不代表供应商一定可用，真实模型
  ID、套餐门槛和能力由服务端配置。
- 聊天注册表支持 Claude 4.5 Haiku、GPT 5.6 Luna、Gemini 3 Flash、GPT 5.6 Terra、Claude 5
  Sonnet、Gemini 3.1 Pro、GPT 5.6 Sol、Claude 5 Opus，并由服务端统一返回可用性与套餐门槛。
- 报告可以持久保存并回溯授权来源；成员报告只能读取该成员主动共享到当前空间的记忆，默认
  仅报告创建者可见。
- 所有成员可以创建对齐议题，但每位成员只能确认、修正或撤回自己的观点。AI 只提出候选差异，
  第一版由 workspace OWNER 发布最终决定，并保留未确认状态与保留意见。
- 长任务在入队时预留 credits，成功后结算，失败、取消或超时后释放；credits 永远不改变访问
  权限。

## Representative interactions

1. 把我刚才的想法整理成一篇 Markdown，但不要改变原意。
2. 把这篇草稿改得更简洁，并保留关键理由。
3. 之前我对这个商业模式的看法是什么？
4. 我以前有没有出现过类似想法？分别是什么时候？
5. 更新当前记忆，但不要在时间线中创建新条目。
6. 把这次变化保存为新版本，保留原来的时间点。
7. 读取这张会议白板照片，把能确认的文字整理成 Markdown，不清楚的地方标出来。
8. 联网对比最新的同类产品，把结论优化后加入右侧，并保留来源。

这些交互将成为草稿修改、版本行为和个人检索质量评测集的起点。

## Non-goals for v0.1

- 普通文件、音频、视频、网页或第三方知识库导入。
- 把 PDF 作为可任意浏览、分享或下载的通用网盘附件。PDF 只作为受保护的当前轮来源或
  已确认记忆的页级引用来源；用户确认后的 Markdown 摘要或摘录才成为记忆正文。
- 移动端原生应用和浏览器插件。
- 账号邀请、找回密码、复杂组织层级、细粒度群组分享和企业 SSO。
- 自动标签、知识图谱或完全自动化的主题体系。
- 定时周报、消息推送和会议系统集成。
- 用 AI 推断用户心理、绩效或未明确记录的经历。
- 微服务、Kubernetes、多区域高可用或大规模商业计费系统。
- 本地模型部署；v0.1 只保留可替换接口。

## Non-goals for v0.2

- 共享 conversation、公开 conversation 链接或团队共同编辑 conversation。
- 跨空间统一搜索、跨空间报告或把一个 memory 同时发布到多个空间。
- 团队邀请、成员移除、复杂角色、企业 SSO 和组织层级树。
- 删除空间、转移所有权、细粒度群组或点对点分享。

## Privacy and AI processing

- 用户记录可能被发送到配置的外部 AI 中转服务，用于 embedding、问答和报告生成。
- 产品测试前必须向四位用户明确披露该处理方式并获得同意。
- 发送给模型的内容必须先经过服务端权限过滤，只包含完成当前请求所需的最小记录集合。
- API Key 仅保存在服务器或开发者本机的未跟踪环境变量中，不进入客户端、不提交到 Git。
- 在引入企业用户前，需要重新评估供应商条款、数据保留、日志、跨境处理和本地模型方案。

## Validation experiment

四位测试者连续使用两周，每人至少保存十五条真实 Markdown 记忆，并完成 AI 整理、手动修改、个人找回、更新当前记忆和保存为新版本。

### Primary v0.1 signals

- **持续记录**：四位用户中至少三位达到十五条真实记录。
- **草稿可控**：AI 修改只进入编辑区，用户确认前不自动保存；测试者认为修改没有改变核心原意。
- **检索可信**：测试者认为至少 80% 的评测回答找到了正确或有用的记录。
- **引用完整**：所有事实性回答都附有当前用户可访问的来源；自动化越权测试为零泄漏。
- **修订可信**：更新当前记忆和保存为新版本的时间线行为符合预期，旧正文始终可以恢复。
- **记录摩擦低**：测试者能在约十五秒内完成一条纯文本记录。

团队验收额外要求：成员只能看到同一团队内主动共享的他人记忆；其他成员私有记忆在列表、
详情、检索、AI 上下文、引用和报告中均不得出现。测试者需完成创建或加入团队、共享一条记忆、
识别作者并撤回共享的闭环。

## Risks and assumptions

- 用户可能不愿额外打开一个 Web 产品记录想法，记录入口的摩擦是首要采用风险。
- AI 整理可能在语言变得流畅的同时改变原意，用户确认和可恢复修订是必要边界。
- “更新当前记忆”和“保存为新版本”的差异可能不够直观，需要通过时间线行为验证。
- 语义相似不等于观点相同，结果必须允许用户检查原文。
- 外部中转服务的模型、接口稳定性和数据处理方式可能变化，必须隔离供应商依赖。
- “可扩展到其他产品”暂时只通过清晰模块边界实现，不提前构建通用平台。
