# Memora AI Native 工作台需求（简版）

Status: Approved for implementation

Date: 2026-08-07

## 1. 产品定位

Memora 不只是记忆库，而是一个基于个人和团队记忆工作的 AI 协作空间。

核心目标有两个：

1. 把记忆自动转化为科研图片、思维导图、流程图等视觉成果。
2. 帮团队理解“我们知道什么、谁持有什么观点、哪里尚未对齐、最后做了什么决定”。

AI 可以提炼、比较和提出建议，但不能读取无权访问的记忆，也不能替用户做最终决定或修改
正式记忆。

## 2. 产品原则

- **默认私有**：个人记忆和新生成内容默认只有本人可见。
- **证据优先**：事实、观点、报告和图形都能回到原始记忆，并显示作者和时间。
- **不猜人心**：不推测成员动机、态度或心理状态，只总结明确表达过的内容。
- **人来确认**：AI 识别的分歧、关系、决策和任务都需要用户确认。
- **可撤回**：来源失去权限后，相关共享报告和图片立即停止展示，等待重新生成。
- **不做监控**：不生成个人绩效排名、忠诚度、情绪分数或隐藏的成员档案。

## 3. 核心能力

| 模块 | 用户得到什么 |
| --- | --- |
| 科研绘图 | 根据提示词或记忆生成科研图片、思维导图、流程图和知识关系图 |
| 记忆问答 | 对个人或团队记忆提问，答案包含作者、时间和原始记录引用 |
| 记忆报告 | 生成本人、成员、团队、项目或主题报告 |
| 分歧对齐 | 识别候选分歧，展示各方明确观点、共同点和待确认问题 |
| 决策记录 | 保存最终决定、理由、备选方案、负责人和复盘时间 |
| 知识缺口 | 找出缺少证据、互相矛盾、长期未更新或无人负责的内容 |
| 团队速览 | 提供“我错过了什么”、会前简报、周期摘要和新人 onboarding |

## 4. 科研绘图

### 4.1 绘图首页

“科研绘图”进入后首先展示模板与历史作品画廊，不直接显示空白画布。

页面包含：

- 科研插画、思维导图、流程图、概念图、时间线等示例。
- 提示词输入框。
- 从记忆库选择内容的入口。
- 绘图引擎、模板、比例、数量和预计 credits。
- 科研风格增强、水印处理和输出语言设置。
- 最近作品与生成历史。

整体保持黑色主视觉，深蓝只作为选中和主要操作色。

### 4.2 记忆选材

用户可以从当前个人、团队或家庭空间选择记忆，并支持：

- 关键词、标题和时间筛选。
- 团队空间按成员筛选。
- 多选记忆并查看作者、时间和可见性。
- 根据提示词推荐相关记忆；推荐结果必须由用户确认。

### 4.3 两种生成方式

| 类型 | 实现方式 | 适合内容 |
| --- | --- | --- |
| 结构化绘图 | AI 先生成节点和关系，再用 React Flow/SVG 渲染 | 思维导图、流程图、时间线、架构图 |
| 图片生成 | 调用图片模型生成多个候选版本 | 科研插画、概念视觉、科普图片 |

文字密集型图不能依赖图片模型直接“画字”，必须保持文字正确且可编辑。现有框图编辑器作为
结构图生成后的精修页面，用于改文字、拖动、连线、重新布局和导出。

### 4.4 结果能力

- 展示“读取记忆、提炼结构、生成布局、渲染图片”等安全过程状态，不展示隐藏思维链。
- 由记忆生成的节点可以查看原始记录、作者和时间。
- AI 推断的关系标记为“待确认”。
- 支持保存版本、重新生成、生成变体和历史恢复。
- 结构图导出 PNG、SVG、PDF；普通图片至少导出 PNG。
- 失败、取消或权限校验失败不扣 credits；成功结果只扣一次。

## 5. AI Native 团队协作

### 5.1 记忆报告

| 报告 | 内容 | 权限 |
| --- | --- | --- |
| 我的记忆报告 | 最近主题、已做决定、未完成事项、观点变化和待整理内容 | 仅本人 |
| 成员贡献报告 | 某成员明确共享的观点、贡献、决定和未完成承诺 | 仅使用团队共享记忆 |
| 团队报告 | 重要进展、决定、风险、分歧、行动项和新增知识 | 当前团队成员 |
| 项目/主题报告 | 围绕选定项目、标签或时间范围形成专题报告 | 继承来源权限 |

所有报告必须：

- 支持时间、成员、主题和 workspace 筛选。
- 为事实结论附带原始记忆引用。
- 区分事实、个人观点、建议、决定和待办。
- 允许用户修正后保存为一条新记忆，不覆盖原始记忆。
- 一键生成对应的时间线、思维导图或项目流程图。

“成员贡献报告”不能读取对方私有记忆，不能评价能力、性格、态度或绩效。

### 5.2 分歧对齐

系统可以识别同一主题下可能不一致的明确观点，但只能称为“候选分歧”，不能直接判定谁对
谁错。

每个对齐议题展示：

- 议题和背景。
- 每位成员最近一次明确表达的观点及来源。
- 已有共识。
- 尚未统一的假设、目标、事实或方案。
- 缺少的证据。
- AI 建议的澄清问题和可验证方案。

对齐流程：

```text
AI 发现候选分歧
-> 参与者确认或修正自己的观点
-> AI 提炼共同点和关键差异
-> 团队讨论并选择方案
-> 保存决定、理由、负责人和复盘时间
```

成员没有明确表达过观点时，必须显示“尚无记录”，不能替成员补充立场。成员后来改变观点时，
系统显示时间变化，并以最近一次经本人确认的表达为当前立场。

### 5.3 决策记录

团队可以把对齐结果保存为决策记录，包含：

- 最终决定与适用范围。
- 决策理由和采用的证据。
- 被放弃的方案及原因。
- 负责人、行动项和截止时间。
- 复盘日期。
- 被替代的旧决定。

当新记忆与现行决定可能冲突时，系统提醒团队复核，但不会自动修改决定。

### 5.4 团队速览

系统提供以下入口：

- **我错过了什么**：总结用户离开期间的新决定、分歧、风险和行动项。
- **会前简报**：围绕会议主题汇总相关记忆、未决问题和需要对齐的观点。
- **周期摘要**：每天或每周生成团队变化报告，由用户主动订阅。
- **新人 onboarding**：按角色生成项目历史、术语、关键决定、成员分工和推荐阅读。
- **交接报告**：整理项目现状、关键上下文、待办、风险和接手建议。

### 5.5 知识缺口和团队记忆健康

AI 可以提示：

- 结论没有来源或证据不足。
- 同一事实存在不同版本。
- 决定没有负责人、截止时间或复盘日期。
- 重要问题长期没有答案。
- 旧决定可能已经过期。
- 某项知识只掌握在一位成员的共享记录中，存在交接风险。

这些都是建议，不自动修改或删除任何记忆。

## 6. 三条核心用户流程

### 从记忆生成一张图

```text
选择 workspace 和记忆
-> 选择图类型或模板
-> AI 生成结构预览
-> 用户确认关系
-> 渲染、编辑、保存或导出
```

### 对齐团队分歧

```text
选择主题和时间范围
-> AI 提取候选观点
-> 各成员确认自己的表达
-> 查看共识、差异和证据缺口
-> 保存团队决定
```

### 生成记忆报告

```text
选择本人、成员、团队或项目
-> 设置时间和主题
-> AI 生成带引用报告
-> 用户修正
-> 保存为新记忆或生成图表
```

## 7. 权限边界

- 所有检索先执行身份、workspace 和 visibility 过滤。
- 个人私有记忆不能进入他人的报告、候选观点、图片、prompt、日志或引用。
- 团队报告只使用成员主动设为 `WORKSPACE` 的记忆。
- 新报告、图和对齐议题默认私有，用户主动操作后才共享。
- 来源撤回后，包含该内容的共享衍生物立即暂停展示并要求重新生成。
- 管理员管理成员和团队设置，但不能查看成员私有记忆。
- 所有 AI 生成结论都显示来源范围、生成时间和“AI 提炼”标记。

## 8. MVP 优先级

### P0

- 科研绘图首页、模板画廊和记忆选择器。
- 从记忆生成思维导图、流程图和时间线。
- 提示词生成科研图片。
- 我的记忆报告、成员贡献报告和团队周报。
- 候选分歧、观点确认、共识/差异展示和决策记录。
- 来源引用、默认私有、撤权保护、版本和 credits。

### P1

- 会前简报、“我错过了什么”和新人 onboarding。
- 知识缺口、过期决定和交接风险提醒。
- 图片局部重绘、参考图、高清化和更多科研模板。
- 报告与图形的订阅式周期生成。

### 暂不实现

- 自动替团队做决定。
- 个人绩效、情绪、性格或忠诚度分析。
- 多人实时共同编辑同一张图。
- 无鉴权的公开分享链接。

## 9. MVP 验收

- [ ] “科研绘图”首先展示画廊和输入框，而不是空白画布。
- [ ] 用户可以从授权记忆生成可编辑的思维导图或流程图。
- [ ] 用户可以通过提示词生成科研图片并保存历史版本。
- [ ] 图和报告中的事实可以回到原始记忆，并显示作者和时间。
- [ ] 用户可以生成本人、指定成员、团队和项目报告。
- [ ] 成员报告只使用该成员主动共享的内容，不产生评价或排名。
- [ ] 系统能展示候选分歧、各方明确观点、共同点和待确认问题。
- [ ] 没有明确观点的成员不会被 AI 虚构立场。
- [ ] 对齐结果可以保存为带负责人和复盘日期的决策记录。
- [ ] 私有记忆不会泄漏到任何团队衍生内容。
- [ ] 失败任务不扣 credits，成功任务只扣一次。
- [ ] 桌面和移动端均可完成绘图、报告和分歧对齐主流程。

## 10. 待确认

1. 每类任务的最终 credits 价格；开发阶段先使用服务端配置值。
2. P0 优先支持的科研领域模板。
3. “成员贡献报告”是否需要成员单独开启，还是共享记忆即代表允许被团队汇总。
4. 分歧议题由所有成员都能创建，还是仅管理员和议题参与者创建。
5. 决策记录是否需要审批人或多数成员确认后生效。

## 11. 与当前实现的关系

- 当前 React Flow 框图编辑器保留，调整为 AI 结构图生成后的编辑步骤。
- 当前 `Knowledge diagrams` 文档与 ADR-0007 没有覆盖生图、报告、分歧对齐和决策记录。
- 本需求确认后，需要更新 Product Brief、新增 ADR，并创建 Web、API、worker、数据库和受保护
  图片资产的实施计划。
