# ADR-0006: Asynchronous document pipeline and page citations

Status: Accepted

Date: 2026-08-07

## Context

同步读取 PDF 会占用聊天请求的完整超时预算，扫描页无法可靠处理，也无法向用户展示排队、
OCR、重试或失败状态。仅把整段抽取文本塞进模型还会丢失页码，并使已保存摘要无法证明其
来源。与此同时，Memora 不能把 PDF 扩展成绕过 workspace 和 visibility 的通用文件库。

## Decision

1. PDF 先作为 PostgreSQL 中的受保护 asset 保存，并在同一事务中创建解析作业；聊天请求不
   同步解析文件。
2. 共用 Worker 在明确的文件大小、页数、字符数、总时间、单页 OCR 时间、并发与重试上限内
   抽取文本。只有低质量或无文本页调用本地 Tesseract，OCR 不可用时返回可操作的降级状态。
3. 抽取结果按页、标题和章节边界保存为 chunk；每个 chunk 独立维护 embedding 状态，外部
   embedding 失败不能丢失资产或阻塞文本检索。
4. 文档检索先执行用户、workspace、owner、分享状态和删除过滤。模型只能引用服务端提供的
   chunk ID，不能提交自造页码、摘录或资产 ID。
5. 正式记忆仍由用户明确确认后创建。记忆保存页级引用快照，正文不自动包含整份 PDF。
6. 被活动记忆引用的来源资产可由有权读取该记忆的用户打开；取消共享立即收回非作者访问。
   删除资产会软删除原始内容并清除解析作业、页、chunk、向量和引用。
7. 公开 Agent 事件、指标、审计和常规日志只记录 ID、状态、数量、错误码和耗时，不记录
   文档正文或模型隐藏推理。

## Consequences

- 上传与可用于对话之间存在短暂异步等待，但用户能看到真实进度并取消或重试。
- 部署镜像需要 Poppler 和 Tesseract 简体中文/英文语言包，镜像体积增加。
- 数据库新增作业、页、chunk 和引用表；常规应用回滚保留这些向前兼容表，灾难恢复才执行
  schema 降级。
- 页级来源变得可审计，删除与取消共享可以沿授权关系传播；未来支持其他文档类型时仍必须
  复用同一受保护资产和授权边界，不能另建无权限过滤的索引。
