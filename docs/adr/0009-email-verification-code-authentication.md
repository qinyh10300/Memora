# ADR-0009: Email verification-code authentication

Status: Accepted

Date: 2026-08-09

## Context

Memora 已使用数据库 session、Argon2 密码和四个开发 seed 账号。产品现在需要邮箱验证码注册
和登录，但不能破坏密码登录，也不能把短时验证码写入日志、审计或长期明文存储。邮件供应商
尚未固定，因此身份领域不能绑定某个厂商 SDK。

## Decision

1. 保留 `/auth/register`、`/auth/login`、密码修改和四个 seed 账号；邮箱验证码是并行认证
   方式，不是迁移或替换密码。
2. 新增 `email_verification_challenges` 表。挑战绑定规范化邮箱和 `REGISTER` / `LOGIN` 用途，
   只保存 HMAC 摘要、过期时间、剩余尝试次数、创建时间和消费时间。
3. 验证码使用安全随机数生成，短时有效且单次使用。申请新验证码会使该邮箱同用途的旧挑战
   失效；发送和校验分别限流，错误会消耗尝试次数。
4. 注册验证码成功后仍要求设置密码，并在同一事务中创建用户、个人 workspace、OWNER
   membership、审计事件和 session。验证码登录复用现有数据库 session。
5. 邮件通过供应商无关的 `VerificationCodeSender` 端口发送。首个 adapter 使用标准 SMTP，
   具有明确超时且不自动重试；测试环境使用进程内投递器，验证码不进入 API 响应或日志。
6. 邮箱验证码默认关闭。显式启用时必须提供 SMTP host 和发件地址，认证配置不完整会在启动
   配置校验中失败；运行时投递失败回滚新挑战并返回可重试错误。
7. 请求未知登录邮箱或已注册的注册邮箱返回相同的 202 结构，但不发送邮件、不创建可验证
   挑战，降低直接账号枚举风险。

## Consequences

- 生产启用前需要独立 SMTP 凭据、发件域名配置和投递监控。
- 同步 SMTP 调用会占用一次短请求，但有 30 秒以内的硬超时；出现真实吞吐需求后再评估
  outbox 邮件任务，不能提前引入第二个服务。
- 旧应用可以忽略新增表，回滚时可保留未消费挑战直至自然过期。
- 验证码注册账户仍拥有 Argon2 密码，因此可以继续使用密码登录和现有密码管理流程。
